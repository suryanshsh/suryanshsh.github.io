A benchmark for statistical judgment

Can an AI analyst resist a tempting A/B test?

OCE‑Bench turns the everyday ship / kill / iterate decision into a graded exam — 45 online‑experiment tasks, nine of them laced with certified statistical traps that reward a confident wrong answer. We built the corpus, packaged it as a runnable container benchmark, and put a frontier agent through every task. Here is the whole process, the logic behind it, and what we found — in short, a real agent lands mid‑ladder: fluent on the textbook analysis, but blind to the two traps that demand a proactive integrity check.

01 — THE PROBLEM

Shipping on a number that lies

Most A/B tests end with one artifact: a lift and a confidence interval. A competent analyst does not ship on that number alone — they first ask whether the number is trustworthy. Was the split actually random? Did a counter‑metric regress? Is the aggregate hiding a subgroup reversal? Was the test stopped the moment it looked good?

Each of those questions is a place where a lazy or over‑eager analysis reaches the wrong decision with high confidence. That is exactly the failure mode we want to measure in AI agents that are increasingly asked to read experiment data and make a call. OCE‑Bench isolates the decision to a three‑way choice and grades it against ground truth:

  • ship — you are confident the true effect clears the practical bar (δ = 0.02).
  • kill — you are confident the true effect is below the bar.
  • iterate — the evidence is inconclusive; you cannot yet tell.

Every task is generated from a known data‑generating process, so the correct decision is not a matter of opinion — it is recomputed from the hidden truth by the grader. The interesting tasks are the ones engineered so that the obvious analysis and the correct analysis disagree.

02 — THE DESIGN

How a trap is certified honest

A trap is only fair if it is genuinely solvable from the data the agent is given, and genuinely catches the shortcut. We enforce both with the same scorer.

Known‑effect generators

Every task is drawn from a closed‑form data‑generating process (Bernoulli funnels, a temporal trajectory, a mix‑shift generator) whose true effect is known exactly — stronger than any estimation cross‑check. The A/A calibrates at α; the estimator recovers the planted effect.

The two‑gate verifier

A submission passes only if it clears a structural pre‑gate and its decision lands in the acceptable set recomputed from the hidden seed. Score is a hard 0 / 1.

Discrimination, not vibes

Each trap ships with a reference oracle (the correct analysis) and a lazy adversary. A seed is only certified as a trap instance when the oracle scores 1 and the adversary scores 0 on the identical verifier. If the shortcut isn't punished, it isn't a trap.

Leak‑proof & un‑gameable

The agent sees public columns only; the grader regenerates the data from a hidden seed. The corpus is balanced 15 ship / 15 kill / 15 iterate, so no constant policy beats chance, and a scanner flags any policy whose answer doesn't move when the evidence is destroyed.

Fixed rules across all 45 tasks. practical bar δ = 0.02 · significance α = 0.05 · guardrail tolerance 0.005 · SRM alarm 0.001. Decision rule: CI_low ≥ δ → ship; CI_high < δ → kill; otherwise iterate.
03 — HOW THE DATA IS MADE

Synthetic by design, so there's an answer key

Real experiment data never arrives with the true effect attached — which is exactly why you can't use it to grade an analyst. OCE‑Bench sidesteps that by generating every task from a small statistical recipe with the correct answer baked in. Plant the truth, and you can mark any decision right or wrong against it, exactly.

Choose the honest answer first.

A family (say clean_ship) and a difficulty tier fix the true effect and the number of visitors — before a single data point exists.

Split the visitors.

Tens of thousands of simulated visitors are randomly assigned to control (the current experience) or treatment (the new one).

Draw each outcome.

Whether a visitor converts is a weighted coin flip — a Bernoulli draw. Control converts at a base rate; treatment at that rate plus the planted effect.

Pin it with a seed.

A random seed freezes every coin flip so the whole dataset regenerates byte‑for‑byte. That is how the grader rebuilds the truth on demand without ever storing it on disk.

For a trap, bend exactly one thing.

Drop a biased slice of one arm (SRM), give the arms a different subgroup mix (mix‑shift), roll the data out day‑by‑day so it briefly looks significant (peeking), or lift conversions while quietly raising refunds (guardrail).

Some tasks use a richer funnel generator — visit → add‑to‑cart → purchase, with a downstream refund guardrail — where a hidden visitor “intent” type couples the metrics realistically (eager buyers convert more and return more). The true effect is still exact and known in closed form, so the correct decision is never a matter of opinion.

What the agent sees — and what it doesn't

Public · handed to the agent
  • arm — control (0) or treatment (1)
  • converted — the primary outcome
  • carted, refund — funnel step & guardrail
  • segment — a pre‑treatment attribute
  • arrival_day — for time‑based tasks
Hidden · grader only
  • the random seed
  • the true effect and its size
  • the family and difficulty tier
  • the acceptable answer set

The agent must reach the right call from the public columns alone — and the expert reference policy proves that is always possible.

08 — WHY IT FAILS

The same shortcut, twice

Every one of the six genuine misses is the same move: compute a competent aggregate difference‑in‑means on the primary metric, see the interval clear δ, and ship — skipping the validity check that a careful experimenter runs unprompted. The two families expose two different missing checks.

Sample‑ratio mismatch — the arms it never counted

The instruction says the experiment was configured for a 50/50 split. In the SRM tasks the realized split is nowhere near it — the treatment arm is missing a large, non‑random slice of its users, which biases the effect. A single arm‑count and chi‑square would raise a five‑alarm fire. Claude never ran one; it shipped all three.

Mix‑shift — it looked at the segment, then ignored it

The mix‑shift tasks are subtler. Here the agent did load the segment column and even print its distribution — but it treated segment as descriptive metadata, never checking the segment mix per arm and never computing the within‑segment effect. Both are decisive, because this is a textbook Simpson's reversal.

These are legitimate misses, not unfair tasks. The corpus hands the agent everything it needs — the arm labels for SRM, a segment column explicitly named a pre‑treatment covariate for mix‑shift. The gap is process: a fluent surface analysis with the deeper validity checks skipped. That is precisely the behavior the benchmark is designed to surface.
09 — FAIRNESS & ROBUSTNESS

Ruling out the wording as the cause

One reasonable worry: the SRM instruction originally asserted the split was 50/50 as fact, which could over‑reassure the agent. So we reworded it to state design intent — "configured to split 50/50" — without ever naming SRM or hinting to check balance, and re‑ran the three tasks.

The result was identical: the same three ship decisions, the same effect estimates, the same reasoning that never inspects the arm counts. The reword changed nothing — which confirms two things at once: the miss is a genuine capability gap, not an artifact of the phrasing, and the trap remains fair under a more neutral framing.

A note on "just tell it to check." Adding "run an SRM check" or "stratify by segment" would lift the score — and quietly destroy the measurement. It converts a test of proactive judgment into a test of checklist‑following, the exact saturation the design avoids. The failures are the signal worth keeping; if you want to study guidance, do it as a separate, labelled condition — not a silent edit to the headline number.
10 — LIMITATIONS

What this does — and doesn't — establish

A result is only as strong as its caveats are honest. Five bound the claims above.

  • One model, one run. We report a single pass of Claude Sonnet 4.5 per task (n = 1), with no repeated sampling — so a borderline task carries no variance estimate. Read per‑task outcomes as points, not distributions.
  • A small, coarse corpus. 45 tasks, three to nine per family. A 0/3 family is a clear signal but rests on three instances; a larger corpus would tighten every per‑family rate.
  • Synthetic data. Generating from known processes is what makes exact grading possible, but real logs are messier — missing data, drift, many metrics at once. The traps are faithful in mechanism, not in every real‑world texture.
  • Textbook traps, so a ceiling risk. The six pitfalls are named and well documented. A model that has internalised the SRM / Simpson / peeking checklist could compress the top of the ladder; the residual is real but thin. Novel, compositional traps are the honest next tier.
  • One harness, default scaffold. These are results for the default claude‑code agent. A different prompt or tool loop could move the numbers — which is exactly why we treat explicit guidance as a separate, labelled condition rather than a silent change.
11 — WHAT IT MEANS

Fluent statistics, incomplete diligence

  • A frontier agent can do the standard experiment analysis well — clean ships and kills, guardrail vetoes, early‑stopping discipline, and underpowering were all handled cleanly.
  • It reliably skips the two proactive validity checks that separate a fluent analyst from a trustworthy one: verifying the randomization (SRM) and conditioning on a pre‑treatment covariate (mix‑shift).
  • The benchmark is informative and unsaturated: 86.7% sits on a calibrated ladder whose ceiling is reachable from public data, with the residual concentrated in a specific, explainable place.
  • The result is robust to a fairer framing of the tasks, and reproducible through a tamper‑evident container harness.

The natural next step is a residual tier of novel and compositional traps — stacking a covariate shift on top of a guardrail, or a clustering / wrong‑analysis‑unit trap — to keep the top of the ladder honest as agents improve.

13 — GLOSSARY

Plain‑language definitions

Every non‑obvious term used above, in one place.

Experiment basics
A/B test online controlled experiment
A live test that randomly shows some users a new version and others the current one, to measure the change's causal effect.
Arm
One side of the test — control (existing experience, arm 0) or treatment (the new one, arm 1).
Conversion rate
The share of visitors who complete the goal action, such as a purchase.
Ship / kill / iterate
The three possible calls: launch the change, drop it, or keep testing because the evidence is inconclusive.
Lift / effect
How much treatment moved the metric versus control.
Percentage points pp
The unit for a gap between two rates: 25% → 28% is a +3pp lift, not “+3%”.
Practical bar δ = 0.02
The smallest lift worth shipping. Beating zero isn't enough — the effect must clear δ.
Guardrail metric
A protective secondary metric (e.g. refund rate) that must not worsen, even when the primary metric improves.
The statistics
Difference‑in‑means
The basic estimate: treatment's average outcome minus control's.
Confidence interval CI
A plausible range for the true effect — wide when data is noisy, narrow when it is plentiful.
Significance / p‑value α = 0.05
A result is “significant” when it is unlikely to be a fluke (p below α). It answers “is it non‑zero?”, not “is it big enough?”.
Statistical power
A test's ability to detect a real effect. An underpowered test has too little data to tell a small true effect from noise.
Bernoulli draw
A single yes/no event modelled as a weighted coin flip — the building block of each visitor's outcome.
Pre‑treatment covariate
A visitor attribute fixed before assignment (like acquisition channel) that affects the outcome but is not caused by the treatment.
Stratification
Computing the effect within each subgroup and combining with fixed weights, so a lopsided subgroup mix can't distort the total.
Aggregate vs. within‑segment
The pooled number over everyone versus the number computed separately inside each subgroup — they can disagree.
The traps
Sample‑ratio mismatch SRM
When realized arm sizes differ from the intended split by more than chance allows — a red flag that assignment or logging is broken, so the effect can't be trusted.
Chi‑square test
A standard check for whether observed counts (like arm sizes) stray from what was expected — used to detect SRM.
Simpson's paradox mix‑shift
When a trend in the pooled data reverses inside every subgroup, caused by the arms carrying different subgroup mixes.
Peeking
Repeatedly checking a running test and stopping the moment it looks significant — which badly inflates false positives.
Guardrail regression
A change that wins on the primary metric but pushes the guardrail past tolerance — a hidden cost that flips ship to kill.
The method
Data‑generating process DGP
The statistical recipe that produces a task's data with a known true effect baked in.
Seed
A number that fixes the random draws so the exact same dataset regenerates every time — the basis for tamper‑evident grading.
Ground truth
The hidden true effect and correct answer, known only to the grader.
Oracle vs. adversary
The reference correct analysis and a deliberately lazy one. A task is certified only when the oracle passes and the adversary fails.
Difficulty tier
Easy / medium / hard settings that widen or shrink the statistical headroom of the correct call.
