Rock-o-net: teaching an LSTM to shred

I wanted to know if a neural network could pick up the phrasing of a lead guitar and improvise its own. Rock‑o‑net pulls electric‑guitar tracks out of MIDI files, learns them with a stack of LSTMs, and then samples back new solos one note at a time. Here is the whole pipeline — from a folder of .mid files to a machine that riffs.

01 — THE IDEA

Can a net learn to play lead?

A lead guitar line is just a sequence — this note, then the next, then the next — with a logic you can feel but struggle to write down. That is exactly the shape of problem a recurrent network is good at: given the last hundred notes, guess the next one. Do that well enough and you can let it run, feeding its own guesses back in, until it has improvised a whole phrase.

So the goal was narrow and honest: model a guitar solo as a sequence of pitches, learn it with LSTMs, and generate new sequences in the same voice. No rhythm model, no dynamics — just the melody and harmony of the notes themselves.

02 — THE DATA

What a MIDI note actually is

MIDI — Musical Instrument Digital Interface — doesn't store audio. It stores instructions. A song is a set of instruments (tracks), each track a list of notes, and each note is really three numbers:

  • Pitch — which note (E4, A3, …).
  • Volume — how hard it was struck.
  • Time step — when it lands relative to the previous note.

Rock‑o‑net keeps only the pitch. That is a big simplification — it throws away dynamics and timing — but it makes the modelling tractable: the whole song collapses into a clean stream of note tokens, which is all the LSTM needs to start learning phrasing.

03 — PARSING

From .mid to tensors

All the real work of a deep-learning project is here, in create_data.py, using the wonderful music21 library to read scores. The recipe, step by step:

Find the guitars.

Walk every .mid file and, using partitionByInstrument, keep only files that actually contain an ElectricGuitar track. The shortlist gets pickled so we never re-scan.

Flatten to tokens.

Recurse through each guitar part: a single Note becomes its pitch string ("E4"); a Chord becomes its pitches joined by spaces ("E4 G4 B4"). The song is now one long list of note tokens.

Slide a window.

Across that list, take windows of 101 tokens: the first 100 are the input X, the 101st is the target Y. Predict the next note from the last hundred.

Toss the boring bits.

Keep a window only if it has more than 13 unique notes. Long repetitive runs teach the model nothing but how to repeat itself.

Encode & standardise.

An OrdinalEncoder maps each token to an integer; X is standardised (subtract the mean, divide by the std) so the network trains cleanly.

One-hot the target.

Y is one-hot encoded so we can train with categorical cross-entropy — the model outputs a probability over the whole note vocabulary. Everything is pickled for reuse.

# the heart of it — window the token stream into (X, Y) pairs
for i in range(0, idx - sequence_length):
    if check_data(data[i:i+sequence_length]):        # >13 unique notes?
        X.append(enc.transform(...data[i:i+sequence_length]))
        Y.append(enc.transform(...data[i+sequence_length]))

X = (X - X.mean()) / X.std()                          # standardise inputs
Y = OneHotEncoder().fit_transform(Y)                  # one-hot targets
The choice that echoes everywhere. By keeping pitch and dropping volume and timing, every downstream decision gets simpler — and the generated music inherits a flat, even rhythm. One line of data design shapes the entire sound of the output.
04 — THE MODEL

A short stack of LSTMs

Nothing exotic — two LSTM layers to carry the melodic memory, dropout to keep it honest, and a softmax head that predicts a distribution over the note vocabulary. 

model = Sequential()
model.add(CuDNNLSTM(256, input_shape=input_shape, return_sequences=True))
model.add(Dropout(0.3))
model.add(CuDNNLSTM(256))
model.add(Dense(128))
model.add(Dropout(0.3))
model.add(Dense(op_len, activation="softmax"))   # prob. over every note

opt = Adam(lr=lr, beta_1=0.9, beta_2=0.999, decay=0.01)
model.compile(loss='categorical_crossentropy', optimizer=opt, metrics=['accuracy'])

Cross-entropy is the natural loss here because the targets are one-hot: the network is really doing classification over “which note comes next”. The two stacked CuDNNLSTM layers are the GPU-accelerated flavour — fast to train, at the cost of pinning you to a CUDA device.

The architecture. Two 256-unit LSTM layers with dropout, a 128-wide dense bottleneck, and a softmax over the note vocabulary.
05 — TRAINING

Three learning rates, 200 epochs each

Rather than guess a single learning rate, I swept three — 0.01, 0.001 and 0.0001 — and trained a fresh model for 200 epochs at each, saving the weights, architecture and loss history every time.

Loss vs. learning rate. Categorical cross-entropy over 200 epochs at each of the three rates — the sweep makes it easy to see which schedule actually settles.

A small irony worth owning: generation later loads the lr = 0.01 model — the most aggressive of the three. Picking the checkpoint by ear rather than by validation loss is exactly the kind of thing a second pass would tighten.

06 — GENERATION

Letting it improvise

Generation is autoregressive. Seed the model with a real 100-note window pulled at random from the training data, ask it for the next note, glue that onto the end, drop the oldest note, and repeat. The window walks forward through music the model is inventing as it goes. 

notes = starting_notes                     # a real 100-note seed
for i in range(length):
    p = model.predict(notes)
    nxt = np.argmax(p[0])                   # greedy: take the top note
    # decode → standardise → slide the window forward one step
    notes = np.append(notes[0, 1:], nxt)...

Then the note tokens are turned back into a score: reverse the standardisation and the ordinal encoding, and for each token build a Note — or, if the token holds spaces, a Chord — assign it an electric-guitar voice, step the offset forward a fixed 0.3, and write the lot out as a fresh .mid. Ten solos, generated end to end.

Two honest tells. The next note is chosen with argmax — greedy and deterministic, so a given seed always plays the same solo — and every note is spaced by the same 0.3 offset, which is why the output has that steady, metronomic feel. Both are direct consequences of modelling pitch alone.
07 — WHAT I'D DO DIFFERENTLY

The honest to-do list

  • Model rhythm and dynamics. Bring back the time-step and volume that step 2 threw away — a solo lives as much in its timing as its pitches.
  • Sample with temperature. Swap the greedy argmax for probabilistic sampling so a single seed can branch into many different solos.
  • Choose checkpoints by validation. Hold out data and pick the learning rate that generalises, instead of defaulting to lr = 0.01.
  • Drop the CUDA lock-in. Plain LSTM/GRU layers would run anywhere; CuDNNLSTM was fast but tied the whole project to one kind of GPU.

None of it takes away from the fun of the first version: a network that had never been told what a guitar is, quietly learning to string notes together into something that sounds like playing.

08 — RUN IT YOURSELF

Three commands

# 1 · parse the MIDIs into training tensors
python create_data.py        # tweak sequence_length / unique_factor here

# 2 · train across the learning-rate sweep
python train.py

# 3 · improvise new solos into music/
python generate.py
